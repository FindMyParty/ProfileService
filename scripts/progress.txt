## Codebase Patterns
- TypeScript + NodeNext: imports must use `.js` extension even for `.ts` source files
- Kysely migration files: use `sql` template literal for custom PostgreSQL types (e.g., `sql\`decimal(10,8)\``)
- Migrator dev/prod detection: `new URL(import.meta.url).pathname.endsWith('.ts')` detects tsx vs compiled JS
- `@types/amqplib` has a type mismatch with `amqplib.Connection`; use `Awaited<ReturnType<typeof amqplib.connect>>` for the connection type and cast internally when needed
- Fastify error handler: cast `error` to `Error & { validation?: unknown }` to safely check for validation errors
- Kysely `ColumnType<SelectType, InsertType, UpdateType>`: use `never` for UpdateType on `created_at`, `Date` for `updated_at`
- PostgreSQL DECIMAL/NUMERIC returned as string by `pg` driver — convert with `parseFloat()` in repository
- `z.input<typeof schema>` for input types (allows optional fields with defaults); `z.infer<typeof schema>` for output types
- docker-compose.yml credentials must align with .env.example: postgres/postgres/profile_service and guest/guest for RabbitMQ
- start.sh adapts skeleton-service pattern: no JWT token (no auth in this service), port 3001, npm run dev for TypeScript
- Postgres health check uses: pg_isready -U postgres -d profile_service
